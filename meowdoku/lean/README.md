# Meowdoku in Lean 4

A small Lean 4 library (core Lean only, no Mathlib) that formalises Meowdoku,
proves the rules of `../RULES.md`, and lets you play a board *through the
proof assistant*: every move is a computable function with a soundness
theorem, and the final "this board has exactly one solution" statement is
checked by Lean's kernel.

```
lake build          # ~2 minutes; the last file evaluates the whole 10x10 solve in the kernel
```

Toolchain: `leanprover/lean4:v4.33.1` (see `lean-toolchain`; `elan` installs it).

## Files

| file | contents |
|---|---|
| `Meowdoku/Basic.lean` | cells, touching, attack, `Board`, `Solution` (column of the cat in each row), the basic "two cats in the same row / column / colour are the same cat" lemmas, and Rule 0 (`not_cat_of_attacks`). |
| `Meowdoku/Rules.lean` | the rulebook, proven for every board: `common_attack`, `knight`, `cap_2x2`, `cap_3x3`, `centre_3x3`, `pattern_2x3`, `pattern_3x4`, `pattern_4x4`, `impossible_2x2`, `impossible_3x3`, `full_3x3`, the abstract counting lemmas `hall1`, `hall2`, `hall3` (rows, columns and colours are all *separating*, so one lemma covers all four directions of Rules 8-10), `edge_2xn` (Rule 11), `what_if` (Rule 12). |
| `Meowdoku/Engine.lean` | the game: a state is a bitmask of crossed-out cells; moves `commonAttack`, `colourMates`, `placeCat`, `hall1/2/3`, `whatIf`; each `Move` carries its soundness proof, `play` chains moves, `unique_of_play` reads off uniqueness. |
| `Meowdoku/Boards.lean` | the hardest 10 × 10 board from `../hardest.json` as data, and its solution. |
| `Meowdoku/Game10.lean` | the 33-move solve of `../WALKTHROUGH.md` (generated by `../make_lean_game.py`), `hardest10_unique`, `hardest10_solution`, `hardest10_exists_unique`. |

## How a play is checked

A move never has a precondition to prove.  Each move computes what it may
remove from its own definition (for example `commonAttack U` removes exactly
the cells attacked by *every* remaining cell of unit `U`), and its soundness
theorem says that no cat of any solution consistent with the state is
removed.  So an illegal or useless move is harmless: it removes nothing.  A
what-if `Move.whatIf x ms` assumes a cat on `x`, plays `ms`, and crosses `x`
out only if some row, column or colour is left with no candidate.

The final check is

```lean
theorem hardest10_unique : ∀ s : Solution hardest10, s.col = sol10 :=
  unique_of_play game sol10 (by decide +kernel)
```

`decide +kernel` makes the kernel evaluate the 33 moves (about a minute).
`#print axioms` reports only `propext` and `Quot.sound`: no `sorry`, no native
code evaluation.

## Playing yourself

Edit `game` in `Game10.lean` (or copy the file for another board from
`../hardest.json`; `Board.ofGrid` turns rows of digits into a board), and use

```lean
#eval IO.println (play game (Cand.all 10)).show     -- '#' open cell, '.' crossed out
#eval (Move.commonAttack (colour 2)).removed (play game (Cand.all 10))   -- what a move would remove
```

The solve is complete when `unique_of_play` type-checks with your move list.

## What is *not* formalised

* The difficulty meter and the search (`../rule_solver.py`, `../hardest.py`)
  are Python.  Lean checks the solve of the board they found, not the claim
  that it is the hardest.
* The general capacity formula cap(a, b) = min(a, b) needs a pigeonhole
  argument on `Fin`; only the specific small boxes the rules use are proven.
* The one-what-if completeness theorem is a finite computation done with Z3.
